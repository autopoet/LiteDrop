# LiteDrop V2 设计说明

V2 是学习定稿版。它不增加用户系统、对象存储或消息队列，而是把 V1
已经存在的业务做得更可靠、更容易解释。

## 1. 优化目标

1. 进程中断后可以恢复，而不是留下永久卡住的任务。
2. 生产配置错误时尽早失败，而不是带着弱配置上线。
3. 每个模块只负责一类问题，路由层不再承载管理业务。
4. 暂停上传时不产生两组并行 worker。
5. 关键流程既有 API 测试，也有真实浏览器测试。

## 2. 后端职责划分

```text
api/
  dependencies.py   客户端 IP 与管理员认证依赖
  admin.py          管理 HTTP 契约
  uploads.py        上传 HTTP 契约

services/
  admin.py           登录限流、概览、列表和删除
  metrics.py         统一计算正式文件与上传分片占用
  recovery.py        恢复中断或超时的合并任务
  upload_locks.py    管理分片级进程锁
  cleanup.py         过期数据与磁盘一致性维护
```

这样调整后，路由只负责读取参数和返回响应；配额检查与管理概览复用同一
份存储统计；清理服务也不再为了释放锁而依赖整个上传服务。

## 3. 合并任务恢复

上传完成请求会先把状态改成 `merging`，再执行耗时的磁盘合并。如果进程
在合并期间退出，数据库会保留这个状态。

V2 的恢复规则：

- 应用启动时，所有遗留的 `merging` 都改为 `failed`。
- 定时维护只恢复超过 30 分钟没有更新的 `merging`。
- 删除可丢弃的 `.merge.tmp`。
- 保留已经校验成功的分片。
- 用户重试时重新执行幂等合并。

启动阶段还没有新请求，因此可以安全恢复全部遗留任务；运行期间则必须
使用时间阈值，避免清理线程碰到正常合并。

## 4. 配置快速失败

`Settings.validate()` 集中校验数值范围和配置关系。`APP_ENV=production`
时还会拒绝：

- 默认或不足 32 字符的签名密钥
- 空口令或包含 `change-me` 的上传口令
- 格式或迭代次数不正确的管理员密码哈希

密码哈希格式由 `core/security.py` 负责，配置模块只调用验证函数，不再
重复解析 PBKDF2 格式。

## 5. 前端暂停状态

V1 点击暂停后立即进入 `paused`，用户快速点击继续时，旧 worker 可能还在
完成已经领取的分片。

V2 增加 `pausing`：

```text
uploading → pausing → paused → uploading
```

每次上传运行都有独立的控制器集合和暂停标记。暂停后不再领取新分片，
最多等待三个在途分片完成；旧运行彻底结束后，继续按钮才会出现。

## 6. 测试层次

- `backend/tests/test_api.py`：完整 API、Range 与下载次数并发。
- `backend/tests/test_v2.py`：配置边界、崩溃恢复和一致性清理。
- `frontend/e2e/upload-download.spec.ts`：真实浏览器上传、取件、下载及
  内容比对。

推荐学习时先跑测试，再沿失败断言进入对应服务代码。

## 7. 明确不做

V2 仍然坚持单机、单 worker、SQLite 和本地磁盘。Redis、Celery、
PostgreSQL、对象存储与多机部署属于业务规模变化后的架构升级，不属于
当前学习项目的必要复杂度。
